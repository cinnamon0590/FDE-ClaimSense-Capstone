## What happened (drill 1, UTC)
- **16:06:17 · fault.** A configuration change pointed the door at `<bucket>-staging` instead of the real document
  bucket. It was made directly on the Lambda, outside `deploy.sh`.
- **16:06:23 · outage begins.** The door failed closed at start-up: it won't serve a different corpus from the one it
  was configured for (D-044). API Gateway answered every call with `500 Internal Server Error`.
- **16:06:32 · user impact.** alice's claim CLM-2024-1800 came back **refused**. Nothing was decided and no data was
  returned, but the label was wrong.
- **16:06:53 · canary detection.** The drill's canary saw 3 failed calls in a row. In production nobody would have
  been paged.
- **16:12:17 · alarm silent.** After 6 minutes the alarm was still `OK`. The roll back was started by hand from the
  runbook: restore the last-good configuration, no rebuild.
- **16:12:23 · recovery.** The rollback was live; the canary was green again at 16:12:50.
- **16:14:17 · recovery verified.** The M3 deployed route check and S3 check both passed, and alice's claim approved
  again at $2,700.

## Root cause and contributing factors
1. **Trigger:** a configuration change that bypassed the release path. `deploy.sh` is the only path that knows the
   right bucket, and it wasn't used.
2. **Why the alarm missed it:** the alarm watched only the door's own metrics (EMF), which the app prints itself.
   A door that can't start prints nothing. Missing data was treated as "not breaching", so the alarm stayed `OK`.
   API Gateway's own `5xx` metric recorded the outage the whole time: 67% at 16:06, then 100% until the rollback.
3. **Why the adjuster was misled:** the orchestrator mapped any non-JSON-RPC answer from the door to
   `invalid_request`, and the pipeline treated every door error as an entitlement refusal.

**What went well:**
- The system **failed closed**: no decision, no data from the wrong bucket, no model spend.
- Rollback was one step, because the last-good configuration was saved before the change.
- Verification used the same checks as M3, plus a real claim.
