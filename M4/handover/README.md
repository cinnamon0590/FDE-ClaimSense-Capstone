# ClaimSense handover pack: start here

**For:** the AutoSure engineer and claims-operations lead who run ClaimSense after the engagement ends. It is
written for someone who never met the team that built it. If you have to ask us something, this pack has a gap:
please file it as an issue.

**What ClaimSense is, in one paragraph:**
- an adjuster opens a motor claim and gets a **first decision in about 15 seconds**: approve with the net payable,
  deny, flag for a senior adjuster, or route to a specialist;
- each decision comes with the reasoning and **citations to the policy clauses it was retrieved for**;
- code owns identity, access, dates and money; models own judgment, and every judgment cites its evidence;
- **a licensed adjuster confirms every outcome**, and nothing is ever paid automatically;
- a user who isn't entitled to a claim gets nothing back, and every call, granted or refused, is in the audit
  trail.

## Your first day (about an hour, $0 except where marked)
1. **Clone, then run the tests and the $0 gate:**
   ```bash
   python -m pytest -q
   (cd M2 && CLAIMSENSE_LLM_REQUIRED=false python evals/run_evals.py --brain replay --suite full)
   ```
   Expect 220 passed, then `DEPLOY GATE: PASS`, 150/150.
2. **Start the whole stack locally with one command:** `cd M3 && make up` (`MOCK_BRAIN=1` for $0). Open the
   console at http://localhost:8501.
3. **Open the deployed console:** https://d2jfndltae6j40.cloudfront.net. Sign in with your own username and
   password (handed over privately, never in the repo; there is no user picker). Run CLM-2024-1800 as alice
   (approve $2,700), sign out, then as carol (refused, no data).
4. **Open the CloudWatch dashboard `ClaimSense-Operations`** and read the six panels against
   [what to watch monthly](watch-monthly.md).
5. **Subscribe your on-call address to SNS `claimsense-alerts`:**
   `ALARM_EMAIL=<address> python M4/ops/observability.py apply`. Confirm the email AWS sends.
6. **Run the door smoke** (`python M4/ops/door_smoke.py`): 5/5 PASS. That's the same check every deploy runs.
7. **Read the two RCAs** ([staged](../drill/RCA-2026-11-23.md), [real](../drill/RCA-2026-11-23-2-mcp-gateway.md)).
   They are the fastest way to learn how this system fails.

## Access and secrets (where they are, never what they are)
| Secret | Lives in | Rotated by |
|---|---|---|
| OpenAI API key | AWS Secrets Manager `claimsense/openai-api-key`, read by the orchestrator's task role at runtime | M2 runbook "Rotate the OpenAI key" |
| Each user's sign-in password | Amazon Cognito (the person's own); the operator's copy only in `~/.claimsense/cognito.json` and `logins.json` (0600) | `python M4/ops/set_password.py <user>`, then hand it over privately |
| Synthetic users' Cognito passwords | generated by `M3/cloud/deploy.sh`; kept only in the operator's `~/.claimsense/cognito.json` (0600) | re-run `deploy.sh` (it keeps or creates them) |
| CI's AWS access | GitHub OIDC role (no stored keys) | `M2/cloud/oidc.sh` |

**Rule:** no secret is ever committed, baked into an image or printed. Every deploy script masks the account id.

## Known limits (honest, as of handover)
- **Synthetic data only.** Before real claim files: a security review (the M1 hard veto), and a held-out set built
  from real-shaped files. Held-out HO-20 showed real-world formats find gaps the synthetic set doesn't.
- **SIU ticketing is a local-only mock.** On AWS, manual escalation uses the runbook's fallback (page SIU on call)
  until a real ticketing system is connected through the door.
- **Adjuster trust (SC-3) is unmeasured on real users.** Measure the confirmation and override rates in month 1.
- **One Fargate task:** fine for a pilot. Add a second task and an autoscaling policy before production volume.
